# Unsupervised Visual Anomaly Detection in Python

Build a small inspection baseline using clean grayscale images. Compare an unseen clean part, a synthetic dent, a bright glint and an illumination shift. The lab prints a score and the location of any tiles that need review.

[Full WIFA Robotics lesson](https://wifarobotics.com/learn/unsupervised-anomaly-detection-vision/)

## Get started

1. Install [Python 3.12 or newer](https://www.python.org/downloads/) if it is missing. On Windows the launcher may be called `py -3`. On macOS and Linux try `python3` if `python` is unavailable. Use the same command for the remaining steps.
2. Download and extract this repository's ZIP from GitHub, or clone it with `git clone https://github.com/williamfarokhzad/wifa-unsupervised-anomaly-detection-vision.git`.
3. Open a terminal in the extracted folder containing `demo.py`. Run:

```sh
python --version
python demo.py dent
python -m unittest discover -s tests -v
```

No third party packages are required for the model, examples or tests. A dent produces `REVIEW; max=8.12; cutoff=2.72; flagged=1`, with tile `(3, 2)` printed next. See [all runnable cases](examples/README.md) for the controls and failure cases.

## What to edit

`demo.py` keeps seven clean training images, four separate clean calibration images and four evaluation cases apart by using different seeds. `anomaly.py` averages each 8 × 8 tile. For each tile position, it stores the median of the training means and a scale equal to the larger of the median absolute deviation and 2 gray levels. The scale prevents a quiet tile from giving an infinite or unstable score. The image score is its maximum tile score. The cutoff is the largest calibration image score plus 1.0. These are teaching settings rather than measured tolerances.

Try replacing the dent's `-64` brightness change with `-12` in `experiment()`, then rerun the dent. A smaller deviation may disappear when averaged with the remaining pixels. Tile coordinates are zero based, listed as column then row. Tiles are coarse regions, so their coordinates do not identify a defect outline.

## Troubleshooting

- If Python says it cannot open `demo.py`, open the folder containing that file.
- `image shape differs from the trained grid` means your new image dimensions differ from the training dimensions. In real work, check registration as well: resizing to the right dimensions does not align a shifted part.
- A glint or a whole frame alert can reflect a capture change. Inspect lighting and fixture alignment before changing the cutoff.
- No alert does not prove a part is clean. A thin scratch can be diluted, and bright and dark changes can cancel inside a tile.

The diagrams use only arrays generated by this project. The editable source is `diagrams/render.py`. To regenerate them, install Pillow into a local environment and ensure DejaVu Sans is available, then run `python diagrams/render.py` from the repository root. Regeneration was checked with Pillow in the preparation environment. Running the project does not require the diagram tooling.

## Scope

This is an offline simulation with generated, perfectly aligned grayscale images. No camera, robot, motion controller, measured production defect, or factory acceptance test was used. This is a simple normal-only baseline, not a reproduction of MVTec AD results and not a product rejection rule. Any hardware pilot needs fixed exposure, registration checks, separately labeled evaluation data across operating conditions and a review path for uncertain samples.
